Remote Job Fit

Remote Job Fit on kokeellinen avoimen lähdekoodin sovellus, jonka tavoitteena on auttaa jäsentämään omaa osaamista ja vertaamaan sitä työpaikkailmoitusten vaatimuksiin. Projekti sai alkunsa omasta tarpeestani kartoittaa osaamistani ja löytää kiinnostavia työrooleja, mutta siitä on kehittynyt yleiskäyttöinen kokeilu, jonka esimerkkiprofiilia ja tehtäväalueita voi muokata omiin tarpeisiin. Mukana on IT:n ja ohjelmistokehityksen lisäksi esimerkiksi mediaan, viestintään, markkinointiin ja visuaaliseen suunnitteluun liittyviä osaamisalueita.

Miten vertailu toimii? Sovellus tunnistaa työpaikkailmoituksesta osaamisvaatimuksia ja vertaa niitä käyttäjän osaamisprofiiliin. Vaatimuksia voidaan luokitella pakollisiin (required), toivottaviin (preferred) ja valinnaisiin (optional) taitoihin. Vertailussa huomioidaan myös ilmoituksessa mainitut osaamistasot sekä kokemuksen vuosimäärät ja tehtävän senioriteettiin viittaavat ilmaukset. Painotettu vertailu auttaa erottamaan keskeiset vaatimukset täydentävistä osaamisista ja tekee näkyväksi sekä osumat että mahdolliset osaamisaukot.

Tutustu Remote Job Fit -projektin lähdekoodiin ja dokumentaatioon GitHubissa. Projekti sisältää Python-pohjaisen työnhakutyökalun sekä TypeScriptillä toteutetun selainkäyttöliittymän, joka yhdistetään paikallisesti käynnistettävään Python-rajapintaan.

Tulosten tulkinta

  • Osumat: profiilistasi löytyvät taidot, joita ilmoituksessa pyydetään.
  • Puuttuvat vaatimukset: ilmoituksesta tunnistetut taidot, joita profiilissasi ei ole. Ne voivat auttaa tunnistamaan mahdollisia oppimistavoitteita.
  • Kokemus- ja senioriteettisignaalit: ilmoituksesta poimitut vuosimäärät ja tehtävän vaativuuteen viittaavat ilmaukset.

Huomioi, että kyseessä on kokeellinen työkalu, ei valmis työnhakupalvelu tai rekrytointiarvio. Tunnistus perustuu koodissa määriteltyihin avainsanoihin ja tekstivihjeisiin, joten tulos ei ymmärrä ilmoitusta samalla tavalla kuin ihminen eikä arvioi todellista osaamistasoa tai soveltuvuutta. Tarkista aina alkuperäinen työpaikkailmoitus. Projektin TypeScript-dashboard on tarkoitettu paikalliseen käyttöön yhdessä Python-rajapinnan kanssa. Julkista selain-demoa ei ole tällä hetkellä julkaistu.

Olio-ohjelmointi

5/5

Sain olio-ohjelmoinnin kurssista arvosanan 5. Aihe kiinnosti minua aidosti, ja olin tutustunut C#:aan jo ennen AMK-opintojani Pelialan perusteet -kurssilla. Olio-ohjelmointi (OOP, object-oriented programming) on ohjelmointitapa, jossa ohjelmaa rakennetaan olioista. Olio yhdistää samaan kokonaisuuteen tietoa eli tilaa ja toimintoja eli metodeja. Luokka toimii olion mallina: esimerkiksi Auto-luokka voi määritellä merkin, mallin ja nopeuden sekä metodit, joilla auto kiihdyttää tai pysähtyy.

Olio-ohjelmoinnin ideana on jakaa ohjelma selkeisiin osiin, joilla on omat vastuut. Kapselointi auttaa hallitsemaan sitä, miten olion tietoja muutetaan. Perintä mahdollistaa yhteisten ominaisuuksien ja toiminnan hyödyntämisen eri luokissa, ja rajapinnat määrittelevät, millä tavalla eri osat voivat toimia yhdessä. Koostamisessa suurempi kokonaisuus rakennetaan pienemmistä olioista. Näiden avulla koodia voi jäsentää, ylläpitää, testata ja laajentaa.

Olio-ohjelmointia käytetään esimerkiksi peleissä, Android- ja muissa mobiilisovelluksissa, verkkopalveluiden taustajärjestelmissä, työpöytäsovelluksissa sekä yritysten järjestelmissä. Pelissä olio voi kuvata pelaajaa, vihollista tai esinettä; verkkopalvelussa se voi kuvata käyttäjää, tilausta tai tuotetta. Olio-ohjelmointi ei ole ainoa tapa toteuttaa ohjelmistoa, mutta se on hyödyllinen silloin, kun järjestelmässä on useita toisiinsa liittyviä tietoja ja toimintoja.

Selaa esimerkkejä nuolipainikkeilla tai valitse tehtävä luettelosta. Koodiesimerkit on lyhennetty ja yleistetty tätä portfoliota varten. Ne havainnollistavat alkuperäisissä tehtävissä käyttämiäni ohjelmointiperiaatteita.

Rajapinta ja jono

CheckoutQueue toteuttaa ICheckoutQueue-rajapinnan ja kapseloi jonon käsittelyn. Rajapinta määrittelee, mitä toimintoja jonon käyttäjä voi kutsua.

public interface ICheckoutQueue
{
    void Join(string customer);
    string? Leave();
    int Length { get; }
}

public class CheckoutQueue : ICheckoutQueue
{
    private readonly Queue<string> queue = new();

    public int Length => queue.Count;
    public void Join(string customer) => queue.Enqueue(customer);
    public string? Leave() =>
        queue.Count > 0 ? queue.Dequeue() : null;
}

MongoDB ja Mongoose -albumimalli

Tehtävässä määritellään Mongoose-skeema albumin tiedoille. Mallissa käytetään pakollisia kenttiä, tietotyyppien tarkistuksia, vuosiluvun rajausta ja automaattisia aikaleimoja.

Mitä ja miksi? Tässä harjoitellaan, miten sovelluksen käyttämä tieto kuvataan tietokantamallina. Albumi toimii esimerkkinä tavallisesta tietueesta, jolla on useita kenttiä ja erilaisia sääntöjä. Tarkoituksena on varmistaa jo tietokantaan tallennettaessa, että tiedot ovat oikean tyyppisiä ja riittävän täydellisiä. Näin myöhemmät API-reitit voivat käsitellä yhdenmukaista ja luotettavaa dataa.

const albumSchema = new mongoose.Schema({
  title: { type: String, required: true, trim: true },
  artist: { type: String, required: true, trim: true },
  year: { type: Number, required: true, min: 1900 },
  tracks: { type: Number, min: 1 },
}, { timestamps: true });

module.exports = mongoose.model("Album", albumSchema);

03

Käyttäjätunnistus ja istunnot

Tehtävässä toteutetaan käyttäjän rekisteröityminen ja kirjautuminen Passport Local Strategyn avulla. Salasana tallennetaan tiivisteenä, istuntoja hallitaan palvelinpuolella ja suojatut reitit tarkistavat kirjautumisen.

Mitä ja miksi? Tässä rakennetaan kirjautumisen perusprosessi: käyttäjä luo tunnuksen, kirjautuu sisään ja saa pääsyn vain hänelle tarkoitettuihin suojattuihin reitteihin. Salasanaa ei tallenneta sellaisenaan, vaan siitä muodostetaan bcrypt-tiiviste. Istunto puolestaan auttaa palvelinta muistamaan kirjautumisen useiden pyyntöjen ajan. Tehtävä havainnollistaa, miten käyttäjän tunnistaminen erotetaan käyttöoikeuksien tarkistamisesta ja miksi salasanojen sekä istuntojen turvallinen käsittely on tärkeää.

const passwordHash = await bcrypt.hash(password, 12); // [bcrypt-hash generated at runtime; never hard-code a password or hash]
const user = await User.create({
  username: username.trim().toLowerCase(),
  passwordHash,
});

req.login(user, (error) => {
  if (error) return next(error);
  res.status(201).json({ username: user.username });
});
04

GET-reitin automaattinen testi

Tehtävässä testataan albumien hakureittiä Jestillä ja Supertestillä. MongoDB Memory Server käynnistää testejä varten erillisen väliaikaisen tietokannan, johon luodaan testidata.

Mitä ja miksi? Tässä ei rakenneta uutta API-toimintoa, vaan tarkistetaan automaattisesti, että olemassa oleva GET-reitti toimii odotetulla tavalla. Testi lähettää sovellukselle pyynnön ja tarkistaa esimerkiksi HTTP 200 -tilakoodin sekä palautettujen albumien määrän. Väliaikainen testitietokanta pitää testidatan erillään oikeasta tietokannasta. Tavoitteena on havaita virheet nopeasti ja varmistaa, etteivät myöhemmät koodimuutokset riko toimivaa hakutoimintoa.

it("returns the albums", async () => {
  const response = await request(app)
    .get("/api/albums");

  expect(response.status).toBe(200);
  expect(response.body).toHaveLength(2);
});
05

POST-reitin automaattinen testi

Tehtävässä testataan uuden albumin lisäämistä sekä virheellisten pyyntöjen hylkäämistä. Testit varmistavat onnistuneen HTTP 201 -vastauksen, puuttuvien kenttien käsittelyn ja virheellisen vuosiluvun hylkäämisen.

Mitä ja miksi? Tässä keskitytään POST-reittiin, jolla palvelimelle luodaan uusi albumi. Testeissä tarkistetaan sekä onnistunut tallennus että tilanteet, joissa käyttäjä lähettää puutteellisia tai virheellisiä tietoja. Esimerkiksi HTTP 201 kertoo, että uusi resurssi luotiin onnistuneesti, kun taas virheellinen pyyntö tulee hylätä asianmukaisella virhekoodilla. Tehtävän tarkoituksena on osoittaa, että API ei ainoastaan toimi oikeilla syötteillä, vaan myös suojaa sovellusta virheelliseltä datalta.

const response = await request(app)
  .post("/api/albums")
  .send({
    title: "Example Album",
    artist: "Example Artist",
    year: 2022,
  });

expect(response.status).toBe(201);
