Titles and factual metadata

Catalogue titles and basic factual fields (creator, release year, country and genre) are curated for this project. We do not copy plot descriptions, reviews, covers, posters, stills or other third-party creative content. Not every metadata field has an individual source URL; uncertain or missing fields are left blank.

DIRECT SOURCES

What the site uses

Active data sourceCC BY 4.0

BookRank

BookRank is the source of numeric reader scores for books in this demo. The browser reads public, read-only JSON category files and imports titles, authors, publication years, scores, rating counts and direct book-page links. The code selects 37 categories and imports up to 1,000 books not already in the local catalogue.

A BookRank score is not simply one platform's average. BookRank describes a Bayesian weighted average that balances a book's reader ratings against the category mean and number of ratings. Its methodology says a title needs at least 50 ratings to enter a ranking. Scores, ranks and confidence values are licensed CC BY 4.0; attribution is BookRank (openbookrank.com).

API, open data and licence ↗Scoring methodology ↗API index ↗

BookRank says ratings are refreshed every three months into dated snapshots. The Vault caches imported records in browser localStorage; this is not real-time and is not a server database. The open-data page reported a 31 October 2026 snapshot when checked.

IMDb

The IMDb link on a work card opens an IMDb search for that title. The demo does not fetch IMDb ratings through an API or copy them into its catalogue. Visitors can check the current score at the original source.

IMDb allows limited non-commercial dataset use under its conditions, but prohibits republishing the data to create a movie database. This project therefore uses a link, not a local copy of IMDb scores.

Rotten Tomatoes

The Rotten Tomatoes link opens a title-specific page when one is configured, or otherwise a search. Tomatometer and Popcornmeter values are not copied into this demo's local catalogue. Current reception should be checked at the source.

Rotten Tomatoes' terms restrict copying, republication and automated collection of site content. Ratings therefore remain on the service; the Vault provides a link only.

Open Library

The Open Library link on a book card creates a search using the title and author. The demo does not bulk-query its API, copy its ratings or download its covers. Open Library says its API is not intended as a third-party bulk data backend and provides monthly data dumps for bulk access.

PROJECT-CURATED MATERIAL

What is maintained here

Catalogue selection

The selection of films, series, animation, games, music, podcasts and documentaries is curated by this project. It reflects the scope of the collection, not a sourced quality ranking or official popularity chart.

Metadata

Creator, release year, genre and country fields have been curated manually in the project's catalogue where identification was sufficiently confident. A separate source URL is not stored for every field; uncertain or missing details are left blank. These fields should not be treated as live-verified.

Personal reviews and suggestions

A visitor's demo review and title suggestion are stored only in that browser's localStorage. They are not sent to a server and are not used as an external source or shared community rating.

Images and interface

This demo does not display posters or book covers from IMDb, Rotten Tomatoes or Open Library. The site's icons are local SVG assets created for the project. The interface, styles and JavaScript behaviour are implemented in this project.

ACCURACY AND RESPONSIBILITY

How to interpret the sources

  • A BookRank score is BookRank's aggregate, not this project's opinion or a single platform's rating.
  • IMDb and Rotten Tomatoes links lead to the source; check the current value on the service itself.
  • A missing score means no source score has been imported into this demo. It does not mean zero.
  • Metadata and catalogue selection are partly manually curated. Errors can be reported through the project's GitHub repository.
  • Source services may change their content, scores, APIs and licences. This page describes the implementation at review time; it does not guarantee permanent availability.
