Olio-ohjelmointi

5/5

Sain olio-ohjelmoinnin kurssista arvosanan 5. Olin aiheesta aidosti kiinnostunut, ja C# oli tullut tutuksi jo ennen AMK-opintoja pelialan perusteet -kurssilla. Olio-ohjelmointi (OOP, object-oriented programming) on ohjelmointitapa, jossa ohjelmaa rakennetaan olioista. Olio yhdistää samaan kokonaisuuteen tietoa eli tilaa ja toimintoja eli metodeja. Luokka toimii olion mallina: esimerkiksi Auto-luokka voi määritellä merkin, mallin ja nopeuden sekä metodit, joilla auto kiihdyttää tai pysähtyy.

Olio-ohjelmoinnin ideana on jakaa ohjelma selkeisiin osiin, joilla on omat vastuut. Kapselointi auttaa hallitsemaan sitä, miten olion tietoja muutetaan. Perintä mahdollistaa yhteisten ominaisuuksien ja toiminnan hyödyntämisen eri luokissa, ja rajapinnat määrittelevät, millä tavalla eri osat voivat toimia yhdessä. Koostamisessa suurempi kokonaisuus rakennetaan pienemmistä olioista. Näiden avulla koodia voi jäsentää, ylläpitää, testata ja laajentaa.

Olio-ohjelmointia käytetään esimerkiksi peleissä, Android- ja muissa mobiilisovelluksissa, verkkopalveluiden taustajärjestelmissä, työpöytäsovelluksissa sekä yritysten järjestelmissä. Pelissä olio voi kuvata pelaajaa, vihollista tai esinettä; verkkopalvelussa se voi kuvata käyttäjää, tilausta tai tuotetta. Olio-ohjelmointi ei ole ainoa tapa toteuttaa ohjelmistoa, mutta se on hyödyllinen silloin, kun järjestelmässä on useita toisiinsa liittyviä tietoja ja toimintoja.

Selaa esimerkkejä nuolipainikkeilla tai valitse tehtävä luettelosta. Koodit ovat lyhennettyjä, yleisiksi muokattuja näytteitä. Ne havainnollistavat tehtävissä käytettyjä ohjelmointiperiaatteita.

Syötteen tarkistus

TryParse tarkistaa, että käyttäjän syöte voidaan tulkita kokonaisluvuksi ennen kuin ohjelma käyttää arvoa. Sama periaate auttaa käsittelemään virheellisiä syötteitä hallitusti.

if (int.TryParse(input, out int score))
{
    Console.WriteLine($"Pisteet: {score}");
}
else
{
    Console.WriteLine("Anna kelvollinen numero.");
}

T9

Konstruktori ja ToString

Vehicle-luokka kokoaa ajoneuvon tiedot yhteen. Konstruktori alustaa olion, ja ToString-ylikirjoitus määrittelee, miten olio esitetään tekstinä.

public class Vehicle
{
    public string Brand { get; set; }
    public string Model { get; set; }
    public int Speed { get; set; }

    public Vehicle(string brand, string model)
    {
        Brand = brand;
        Model = model;
    }

    public override string ToString() =>
        $"{Brand} {Model}, {Speed} km/h";
}

Ehtojen tarkistus luokassa

Hissi-esimerkissä GoTo-metodi tarkistaa kerrosnumeron ennen tilan muuttamista. Metodi palauttaa onnistumisen ja viestin, joten kutsuva ohjelma voi reagoida tulokseen.

public bool GoTo(int floor, out string message)
{
    if (floor < 1 || floor > 5)
    {
        message = "Kerros ei ole sallittu.";
        return false;
    }

    CurrentFloor = floor;
    message = $"Hissi on kerroksessa {floor}.";
    return true;
}

Abstrakti luokka ja ylikirjoitus

Mammal-tehtävässä abstrakti kantaluokka määrittelee yhteisen Move-metodin sopimuksen. Johdetut luokat toteuttavat toiminnan eri tavoin override-avainsanalla.

T23

Rajapinta ja jono

CheckoutQueue toteuttaa ICheckoutQueue-rajapinnan ja kapseloi jonon käsittelyn. Rajapinta määrittelee, mitä toimintoja jonon käyttäjä voi kutsua.

public interface ICheckoutQueue
{
    void Join(string customer);
    string? Leave();
    int Length { get; }
}

public class CheckoutQueue : ICheckoutQueue
{
    private readonly Queue<string> queue = new();

    public int Length => queue.Count;
    public void Join(string customer) => queue.Enqueue(customer);
    public string? Leave() =>
        queue.Count > 0 ? queue.Dequeue() : null;
}
